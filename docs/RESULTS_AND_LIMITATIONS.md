# FP-001 closed-loop evaluation

## Reproduction record

The paired `evaluation.run_closed_loop` runner was rerun for 1,000 calibration scenarios (seed range 100000–100999) and 5,000 held-out scenarios (seed range 400000–404999), using 0.1 MW commitment increments and the configured uncertainty assumptions. The seed ranges are disjoint, the runner records `heldout_data_used: false`, and all controllers receive the same held-out disturbances.

The run completed on 2026-10-15. Wall time was 2,907.16 seconds (48 minutes 27 seconds); the internal evaluation timer reports 2,900.66 seconds and excludes calibration and fixed-schedule setup. Python 3.12.10; NumPy 2.5.4, pandas 3.0.6, SciPy 1.18.1, Pyomo 6.10.1, HiGHS 1.15.1, statsmodels 0.15.0, and PyYAML 6.0.3.

`results/benchmark_summary.json` is a compact tracked summary. `results/closed-loop-controller-comparison.png` is generated by `evaluation.closed_loop_plots`. Full raw files remain locally in `results/closed-loop-fp001-reproduced/` (19.0 MB JSON and 3.34 MB CSV); their SHA-256 values are recorded in the summary. A cross-check recounted event and joint outcomes for all 5,000 rows in the CSV and matched the JSON aggregates for every controller.

All 552 fixed-horizon event failures and all 112 failures for each rolling method were delivery shortfalls. No battery reserve violations, workload deadline misses, recovery failures, or solver failures were observed. Mean recovery solver time was 0.09538 seconds for fixed-horizon and 0.09349 seconds for the rolling controllers.

Rolling risk-aware MPC and RAFC-V had zero discordant event outcomes (paired exact McNemar p=1.0; Holm-adjusted p=1.0). Paired bootstrap 95% intervals for RAFC-V minus rolling risk-aware MPC in delivered MW, shortfall energy, and rebound peak were each [0, 0]. Thus RAFC-V showed **no measured incremental performance improvement** over the fair rolling risk-aware MPC baseline. Both rolling controllers selected 4.9 MW and use the same receding-horizon dispatcher. Rolling methods outperformed the frozen schedule under these disturbances, reflecting their ability to observe and re-optimize as disturbances arrive; that does not demonstrate RAFC-V superiority.

The fixed schedule used the same 4.9 MW RAFC-V commitment and a one-sided 99% meter margin, then remained frozen during held-out events. Its inability to adapt is the intended controller distinction. Rolling risk-aware MPC is the relevant comparator for evaluating the recovery-aware commitment policy.

## Interpretation limits

- These are outcomes under modeled uncertainty assumptions, not measured facility data, field tests, or utility certification.
- The 97.76% estimate and 97.31% Wilson lower bound apply only to this tested configuration and seed range. They are not universal guarantees.
- This rerun reused the previously specified fixed seed ranges. It confirms reproducibility for those seeds, but is not a new independent sample.
- Critical-power uncertainty is common-mode to baseline-relative reductions; inference latency and service quality are not modeled.
- Each disturbance remains constant during one event. Rolling controllers observe it interval by interval; fixed-horizon cannot adapt once its schedule is frozen.
- The 17 MW recovery base is an explicit planning assumption. Workload restoration and battery charging share the 20 MW ceiling.
- Fixed schedule setup is a one-time optimization; rolling runtime is per held-out scenario and should not be compared as the same operation.
- No ablation, recovery sensitivity sweep, independent site-data calibration, or multi-site generalization is claimed.
- Full per-scenario raw files are local and ignored by Git. The tracked summary records checksums; the API reports if raw files are absent and suppresses summary metrics if present files fail those checks.
